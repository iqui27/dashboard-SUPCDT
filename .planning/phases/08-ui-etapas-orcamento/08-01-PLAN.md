  <name>Task 1: Create frontend API modules for etapas and orcamento</name>
  <files>src/lib/api/etapas.ts, src/lib/api/orcamento.ts</files>
  <action>
Create `src/lib/api/etapas.ts` with typed fetch wrappers matching the backend endpoints in `server/routes/modulosEtapasOrcamento.ts`. Each function takes `(projetoId: string, ..., token: string)`, calls the appropriate endpoint, checks `response.ok`, throws on error, and returns `normalizeProjeto(await response.json())` (import from `../../types/projeto`). Functions needed:

1. `createEtapa(projetoId, data: { nome: string; percentual?: number; entregaveis?: { nome: string }[] }, token)` — POST `/:id/etapas`
2. `updateEtapa(projetoId, etapaId, data: { nome?: string; percentual?: number }, token)` — PUT `/:id/etapas/:etapaId`
3. `deleteEtapa(projetoId, etapaId, token)` — DELETE `/:id/etapas/:etapaId`
4. `toggleEntregavel(projetoId, etapaId, entId, concluido: boolean, token)` — PATCH `/:id/etapas/:etapaId/entregaveis/:entId`
5. `addEntregavel(projetoId, etapaId, nome: string, token)` — POST `/:id/etapas/:etapaId/entregaveis`
6. `deleteEntregavel(projetoId, etapaId, entId, token)` — DELETE `/:id/etapas/:etapaId/entregaveis/:entId`

Create `src/lib/api/orcamento.ts` similarly:

1. `createRubrica(projetoId, data: { nome: string; previsto?: number; executado?: number }, token)` — POST `/:id/rubricas`
2. `updateRubrica(projetoId, rubricaId, data: { nome?: string; previsto?: number; executado?: number }, token)` — PUT `/:id/rubricas/:rubricaId`
3. `deleteRubrica(projetoId, rubricaId, token)` — DELETE `/:id/rubricas/:rubricaId`
4. `addAditivo(projetoId, rubricaId, data: { descricao: string; valor: number; data?: string }, token)` — POST `/:id/rubricas/:rubricaId/aditivos`

All functions use `API_URL` from `./base` and follow the same error handling pattern as `src/lib/api/projetos.ts`.

  <name>Task 2: Create EtapasSection component</name>
  <files>src/components/supcdt/EtapasSection.tsx</files>
  <action>
Create `src/components/supcdt/EtapasSection.tsx` that receives `{ projeto: Projeto; onUpdate: () => void }` and renders the Etapas module section.

**Conditional visibility (UIET-01):** If `projeto.modulosAtivos?.etapas` is not `true`, return `null`.

**Layout:** Follow the established card pattern from DetalheProjeto.tsx:
- Outer: `overflow-hidden rounded-[1.35rem] border border-white/80 bg-white/80 shadow-sm`
- Header with label "Execucao" (sky-700/70) + title "Etapas do projeto"
- "Nova etapa" button in header (h-8 rounded-full, outline variant)

**Etapa list (UIET-02):** `divide-y divide-slate-100` list. Each etapa shows:
- Nome (text-sm font-semibold text-slate-950)
- Progress bar (h-1.5 rounded-full bg-sky-600 over bg-slate-100)
- Percentual displayed as "XX%" — on click, switches to an `<input type="number" min="0" max="100" />` (inline edit). On blur or Enter, call `updateEtapa(projeto.id, etapa.id, { percentual: newValue }, token)` then `onUpdate()`. Use local state for optimistic update. Show toast on error.
- Delete button (Trash2 icon, small, text-slate-400 hover:text-rose-600)

**Entregaveis checklist (UIET-03):** Below each etapa's progress bar, render `etapa.entregaveis` as a checklist:
- Each item: checkbox + nome. Checkbox checked = `concluido`.
- On toggle: call `toggleEntregavel(projeto.id, etapa.id, ent.id, !ent.concluido, token)` then `onUpdate()`. Optimistic local state update.
- Delete button (X icon) per entregavel, calls `deleteEntregavel`.

**Nova etapa (UIET-04):** Button in header. On click, show a compact inline form at the top of the list (NOT a modal — use a collapsible form within the card). Fields: nome (text input, required), percentual (number input, default 0). On submit, call `createEtapa` then `onUpdate()`.

**Adicionar entregavel (UIET-05):** Small "+" button below each etapa's checklist. On click, show inline text input. On Enter or blur (if non-empty), call `addEntregavel` then `onUpdate()`.

Use `useAuth()` for token. Use `toast` from sonner for error feedback. Import Lucide icons: `Plus`, `Trash2`, `X`, `Check`, `ListChecks`.

State management: Use `useState` for editing states (editingPercentual, addingEtapa, addingEntregavelForEtapaId). Keep it simple — no useReducer needed.
