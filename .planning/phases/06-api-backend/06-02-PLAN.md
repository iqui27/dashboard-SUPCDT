const COLLECTION = 'projetos_supcdt';

**Helper (mesmo padrão do Plan 01):**
```typescript
async function findProjectOrFail(id: string, res: Response) {
  if (!ObjectId.isValid(id)) {
    res.status(400).json({ error: 'ID de projeto inválido' });
    return null;
  }
  const db = await getDatabase();
  const col = db.collection<DBProjeto>(COLLECTION);
  const projeto = await col.findOne({ _id: new ObjectId(id) });
  if (!projeto) {
    res.status(404).json({ error: 'Projeto não encontrado' });
    return null;
  }
  return { col, projeto, oid: new ObjectId(id) };
}
```

**Endpoints de Parceiros (PARC-01 a PARC-03):**

1. `POST /:id/parceiros` (requireAuth) — PARC-01
   - Body: `{ nome: string, papel: string, status?: DBStatusParceiro }`
   - Valida `nome` e `papel` obrigatórios (400 se ausentes)
   - Valida `status` se presente: deve ser um dos valores de `DBStatusParceiro` ('Ativo' | 'Apoiador' | 'Consultor' | 'Inativo'). Default: 'Ativo'
   - Cria `DBParceiro` com `id: crypto.randomUUID()`
   - Usa `$push: { parceirosModulo: novoParceiro }`
   - Nota: usar `parceirosModulo` (não `parceiros`) para evitar conflito com campo legado `parceiro?: string | null`
   - Retorna projeto atualizado

2. `PUT /:id/parceiros/:parceiroId` (requireAuth) — PARC-02
   - Body: `{ nome?: string, papel?: string, status?: DBStatusParceiro }`
   - Usa `$set` com dot notation e `arrayFilters: [{ 'elem.id': parceiroId }]`
   - Monta `$set` dinamicamente com campos presentes
   - Valida `status` se presente
   - Retorna projeto atualizado

3. `DELETE /:id/parceiros/:parceiroId` (requireAuth) — PARC-03
   - Usa `$pull: { parceirosModulo: { id: parceiroId } }`
   - Retorna projeto atualizado

**Endpoints de Riscos (RISC-01 a RISC-03):**

4. `POST /:id/riscos` (requireAuth) — RISC-01
   - Body: `{ descricao: string, probabilidade: DBProbabilidadeRisco, impacto: DBImpactoRisco, mitigacao?: string | null, status?: DBStatusRisco }`
   - Valida `descricao`, `probabilidade` e `impacto` obrigatórios
   - Valida `probabilidade` in `['Baixa', 'Média', 'Alta']` e `impacto` in `['Baixo', 'Médio', 'Alto']` (400 se inválido)
   - Default `status`: 'Aberto'
   - Cria `DBRisco` com `id: crypto.randomUUID()`
   - Usa `$push: { riscos: novoRisco }`
   - Retorna projeto atualizado

5. `PUT /:id/riscos/:riscoId` (requireAuth) — RISC-02 + RISC-03
   - Body: `{ descricao?: string, probabilidade?: DBProbabilidadeRisco, impacto?: DBImpactoRisco, mitigacao?: string | null, status?: DBStatusRisco }`
   - Valida enum values se presentes
   - Usa `$set` com dot notation e `arrayFilters: [{ 'elem.id': riscoId }]`
   - Monta `$set` dinamicamente
   - Fechar/reabrir risco = alterar `status` para 'Encerrado' ou 'Aberto' (RISC-03 coberto pelo mesmo endpoint)
   - Retorna projeto atualizado

6. `DELETE /:id/riscos/:riscoId` (requireAuth)
   - Usa `$pull: { riscos: { id: riscoId } }`
   - Retorna projeto atualizado

**Endpoints de Governança (GOVN-01 e GOVN-02):**

7. `POST /:id/decisoes` (requireAuth) — GOVN-01
   - Body: `{ titulo: string, data: string, descricao?: string | null, responsavel?: string | null }`
   - Valida `titulo` e `data` obrigatórios
   - Cria `DBDecisaoGovernanca` com `id: crypto.randomUUID()`, `data: new Date(body.data)`
   - Valida que `new Date(body.data)` é uma data válida (`!isNaN(date.getTime())`)
   - Usa `$push: { decisoes: novaDecisao }`
   - Retorna projeto atualizado

8. `PUT /:id/decisoes/:decisaoId` (requireAuth) — GOVN-02 (editar)
   - Body: `{ titulo?: string, data?: string, descricao?: string | null, responsavel?: string | null }`
   - Usa `$set` com dot notation e `arrayFilters: [{ 'elem.id': decisaoId }]`
   - Converte `data` para `new Date()` se presente
   - Retorna projeto atualizado

9. `DELETE /:id/decisoes/:decisaoId` (requireAuth) — GOVN-02 (excluir)
   - Usa `$pull: { decisoes: { id: decisaoId } }`
   - Retorna projeto atualizado

**Endpoints de Indicadores (INDC-01 a INDC-03):**

10. `POST /:id/indicadores` (requireAuth) — INDC-01
    - Body: `{ nome: string, categoria: string, serie?: { label: string, valor: number }[] }`
    - Valida `nome` e `categoria` obrigatórios
    - Cria `DBIndicadorPesquisa` com `id: crypto.randomUUID()`, `serie: body.serie ?? []`
    - Usa `$push: { indicadores: novoIndicador }`
    - Retorna projeto atualizado

11. `PUT /:id/indicadores/:indicadorId` (requireAuth) — INDC-02
    - Body: `{ nome?: string, categoria?: string, serie?: { label: string, valor: number }[] }`
    - Usa `$set` com dot notation e `arrayFilters: [{ 'elem.id': indicadorId }]`
    - Para `serie`, substitui o array inteiro: `indicadores.$[elem].serie: body.serie`
    - Retorna projeto atualizado

12. `DELETE /:id/indicadores/:indicadorId` (requireAuth) — INDC-03
    - Usa `$pull: { indicadores: { id: indicadorId } }`
    - Retorna projeto atualizado

**Padrão de retorno:** Mesmo do Plan 01 — após cada operação de escrita, fazer `findOne({ _id: oid })` e retornar o documento completo.

**Tratamento de erro:** Cada endpoint envolve o corpo em try-catch, logando o erro com `console.error` e retornando `res.status(500).json({ error: 'mensagem descritiva' })`.
